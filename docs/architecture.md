# Architecture

Pocket Flashcards is a static progressive web app. The browser loads
`index.html`, which loads `src/app.js` as an ES module. There is no server
logic and no build step. All data lives in the browser's IndexedDB.

```
ui/  ──►  services/  ──►  core/
(DOM)     (use cases,       (pure functions:
           storage port)     parse, render, schedule, ids)
```

Dependencies point inward only, and ESLint enforces it. Shared shapes are
`@typedef`s in [`src/core/types.js`](../src/core/types.js).

## core/

Pure functions. No DOM, no storage, no `Date.now()` or `Math.random()`:
time and randomness are parameters.

### Scheduling (SM-2)

For a state with `reps = r`, `interval = i` and `ease = e`:

| Rating | Interval (days)                                         | Ease                 | Reps | Lapses        |
| ------ | ------------------------------------------------------- | -------------------- | ---- | ------------- |
| Again  | 0, due in 10 minutes                                    | `max(1.3, e − 0.2)`  | 0    | +1 if `r > 0` |
| Hard   | `r = 0`: 1, else `max(i + 1, round(i × 1.2))`           | `max(1.3, e − 0.15)` | +1   |               |
| Good   | `r = 0`: 1, `r = 1`: 3, else `max(i + 1, round(i × e))` | `e`                  | +1   |               |
| Easy   | `r = 0`: 4, else `max(i + 1, round(i × e × 1.3))`       | `e + 0.15`           | +1   |               |

`due = now + interval days` (or `now + 10 minutes` for Again). A card is
due when `due ≤ cutoff`, where the cutoff is the end of the user's local
day, so a card due later today shows up in this morning's review.

### Review queue

`buildReviewQueue` lists the due cards that aren't suspended, oldest due
first, followed by up to `newLimit` new cards in the order `cards` is given
(callers sort by deck name, then position). A card is **new** when it has
no state or its state has `lastReviewed: null`; suspending a new card
stores an initial state with `suspended: true`, and it stays new. `advanceQueue` drops the head. For Again, it reinserts the
head three places later, or at the end if the queue is shorter, so a
forgotten card comes back in the same session.

## services/

Use cases. They take a storage port and a clock, never touch the DOM, and
are tested against `MemoryStorage`.

| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `storage/storage.js`           | The `Storage` port as a JSDoc `@typedef` with these async methods: `getDecks`, `getDeck(id)`, `putDeck`, `deleteDeck(id)` (also deletes the deck's cards, states and assets), `getCards(deckId?)`, `putCards(cards)`, `deleteCards(ids)` (also deletes their states), `getStates()`, `putState`, `putStates`, `deleteStates(ids)`, `getAssets(deckId?)`, `getAsset(id)`, `putAssets`, `deleteAssets(ids)`, `getReviewLog(since?)` (all entries when omitted), `addReviewLog(entry)`, `getSettings()` (merged over `DEFAULT_SETTINGS`), `putSettings`, `clear()`, and two atomic writes that each run in one transaction: `applyImport({ deck, putCards, deleteCardIds, putAssets, deleteAssetIds })` and `replaceAll({ decks, cards, states, assets, reviewLog, settings })`. Also exports `DEFAULT_SETTINGS`. |
| `storage/memory-storage.js`    | `class MemoryStorage`, implementing the port with Maps.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |
| `storage/indexeddb-storage.js` | `class IndexedDbStorage`, `static open(name = 'pocket-flashcards', { onVersionChange })`. missingImages, errors, warnings, hasDiagrams }`. `diff` holds the
`diffCards` result as counts and lists. Nothing is written until
`commitImport`.

`src/app.js` is the composition root. It opens `IndexedDbStorage`, builds
the services with `systemClock`, applies the theme, starts the router and
registers `sw.js`.

## Service worker

`sw.js` precaches the app shell (`index.html`, `src/**`, the manifest and
icons) under the cache name `pf-<version>`. The version is `dev` locally,
and the Pages workflow stamps it with the commit SHA on deploy. It serves
the shell cache-first; `dev` serves network-first so edits show on reload.
`vendor/` is cached at runtime on first fetch, because Mermaid is large and
only decks with diagrams need it. Activating a new version deletes the old
caches.
